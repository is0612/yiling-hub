# QQ 群聊上下文与话题参与：实施交接方案 v2

状态：方案定稿，尚未实现。
适用：QQ OneBot 普通群聊。交给实施者时以本文为准；v1（`docs/qq-group-context-reply-plan.md`）保留作历史对照，不再作为实施依据。
本轮只写方案，不修改业务代码。

---

## 0. 给实施者的一句话

保留现有「攒批 → 零成本闸门 → 一次模型判断并生成回复」的结构，把四件事做对：

1. **所有群消息走同一条管道**，@ 和水群不再各走一套入口（见 §1.4）；
2. 把「真实 @ 我」和「文字里出现我的名字」分开，名字只当弱线索；
3. 让模型看到**近期群聊上下文**和**每条消息到底在跟谁说话**；
4. 用短期「话题参与」状态支持她继续参与聊过的话题，同时不认领别人的对话。

不新增模型调用次数、不新增分类模型、不新增数据库表、不新增 UI 档位。

---

## 1. 产品目标（已与用户确认）

群聊里保留现有三档 `mention | ambient | all`，但它们只是**同一条管道上的三种放行策略**，不再是三套代码。默认 `ambient` 就是「@ 必回 + 自然接话」并存；用户说的「两种聊天方式」是这条管道里的两种语境：

### 1.1 被邀请参与

- 群友**真实 @** 本账号 = 明确邀请。在现有限额与发送约束允许时，进入「不允许主动沉默」的应答路径。
- 短期记住邀请者的 QQ 身份、触发消息、以及这次参与的话题。
- 之后不要求每句话都 @；但同一 QQ 的后续消息**不等于**同一话题，要按上下文判断。
- 其他人（包括别的鱼）可以加入她已经参与的话题，她可以考虑补充。
- 群友在同一话题里转去 @ / 回复另一条鱼时，**不做一刀切跳过**：她可以补充自己的看法，但不能冒充被询问者，也不能把别人的回答算成自己说过。

### 1.2 自然水群

- 无人邀请时，现有机会闸门放行后，她可以基于近期上下文说一句有内容的话（观点、赞同、补充）。
- 她**没有参与**这段对话、而群友明确 @ 其他账号时，不插话。
- 只出现相同名字/别名/单字昵称，不能确认是在叫她；拿不准就沉默。

### 1.3 核心区分

> 「直接对我说话」和「我参与过这个话题、可以补充」是两种关系，必须分别表示。

3 分钟是「短期关注」的无相关互动失效时间，**不是**：

- 被 @ 后这三分钟内这个人的所有消息都必须回；
- 群里一直有人说话就无限续期。

### 1.4 一条管道（本版核心决定）

现状是三套入口：`mention` 档的 @ 走单条路径（不攒批、无群聊上下文、不能沉默），`ambient` 走攒批，`all` 又回到单条。@ 和自然接话因此在代码层就是两个功能。

本版合并成一条：

```
所有群消息 → 写入同一份有界上下文缓存（无论后面是否回复）
           → 按模式策略决定进不进待判批次
           → 同一个攒批（direct 用短窗口，其余用整轮窗口）
           → 同一份上下文（背景 + 本轮 + 参与锚点）
           → 同一次模型调用 → 同一次发送
```

- `direct`（批次里有真实 @ 她）只是批次上的一个标记：必须回、`allowSilent=false`，仍受日上限、最短间隔、群规、额度约束。
- 其余批次是 `optional`：模型看上下文决定说不说，允许 silent。
- 模式只改变「哪些消息进待判批次」，不改变管道本身：
  - `mention`：只把 direct 消息（以及已参与话题的后续候选，见 §8）送进批次；
  - `ambient`：所有消息都可进批次，由机会闸门筛选；
  - `all`：所有消息都进批次，闸门不筛。

这样 @ 也能拿到上下文，水群不会因为选了「仅 @」被整个关掉，代码与测试也只有一套。代价：@ 也要等 `mentionWindowSeconds`（默认 4 秒）攒批；`all` 从「每条都回」变成「每轮都回」，需要用很短的窗口并在 UI 文案里说清。

## 3. 实施前必须核实的现状

不要直接把本节当结论，逐项在代码里确认：

1. 收消息 → 去重 → 命令路由 → 攒批 的实际顺序（`onebot/serve.ts`、`onebot/runner.ts`）。
2. 结构化 `at` / `reply` 段的形态；CQ 字符串兼容路径；`self_id` 与连接账号 QQ 的兜底（`isSelfMentioned`）。
3. 三档模式、安静时段、日上限、最短间隔、概率、群规限流、额度的真实顺序。
4. `allowSilent` 在 `pipeline.ts` / `chat-reply.ts` 的传递与 `silent` 分支的落库、去重、usage 记账。
5. 按会话串行锁 `enqueueConversation` 覆盖的范围，以及发送成功后的状态更新点。
6. `recentMessages` 的来源、是否已含当前批次、assistant 消息如何标记。
7. 现有测试脚本与运行方式；常驻适配器是否需要重启才能加载改动。

已知问题（v1 已核实，供参考，仍需复验）：

- `serve.ts` 的 `cued` 混合了真实 @ 与名字/别名匹配：ambient 下 `allowSilent: !cue` 使撞名强制回复；mention 下命中名字直接走单条回复。
- `group-chat.ts` 的 `related` 仅由「最近三分钟自己发过言」推导，不能代表对方还在跟她聊。
- `types.ts` 把 at 段拍平成 `@QQ号`，模型无法判断哪个号是自己。
- 闸门丢弃的轮次不落库，导致「别人刚聊了什么」可能不在历史里。
- `chat-reply.ts` 把「叫名字」和「@」写成同一确定级别，且群聊提示受 `allowSilent` 控制。
- 单条路径也有已落库的 `recentMessages`，不是完全没有上下文；真正缺的是被丢弃的近期群聊和稳定的身份/指向信息。
- 结构上 @ 与自然接话是**三套入口**：`mention` 的 @ 走单条路径，`ambient` 走攒批，`all` 又回单条。本版要求合并成一条（§1.4），实施时先确认这三条入口的真实边界。

## 4. 三层分离

### 4.1 消息事实（程序解析，可信）

逐条消息尽量保留：外部消息 ID（字符串）、时间、发送者 QQ（字符串，禁止转 number）、展示昵称（仅展示）、`mentionTargets`（`self | other | all | none | unknown`，可多个）、`replyToMessageId` 与可解析的被引用作者、是否本角色已成功发送。

规则：

- 优先结构化消息段，其次现有 CQ 字符串兼容；不能因为正文出现 `@123456` 就当可靠 @。
- `self` 判定优先用事件 `self_id`；缺失时用连接上已知的账号 QQ（`record.accountQq`）；两者都取不到才标 `unknown`，**不要**把 unknown 当成「一定是别人」，也不要当成「一定是自己」。
- `@全体` 不是直接 @ 自己。
- 群友知道昵称相同/改名频繁：同一 QQ 改昵称仍是同一人；同名不同 QQ 必须是两个成员。
- 不得靠昵称或文风识别其他机器人；未知成员一律按普通外部成员处理。

### 4.2 模型判断（不是事实）

模型可返回可选的 `groupDecision`（见 §11），只是「它怎么理解这轮对话」。它不能：

- 用 `unrelated` 撤销程序确认的真实 @；
- 凭自己返回 `direct` 制造一次真实 @；
- 创造出不存在的 QQ、成员代号、消息 ID、话题锚点。

### 4.3 发送结果（程序确认）

「收到消息」「放进上下文」「模型认为相关」「模型生成了文本」「消息发送成功」是五种状态。

只有**发送成功**才能登记为实际参与。发送失败、`silent`、只调过模型、只通过校验，都不算。重复事件不二次发送、不重复刷状态。`silent` 不发空消息、不写伪 assistant 历史，usage 照现有规则记账。

## 5. 数据结构

新增独立小模块 `server/utils/channel-adapter/onebot/group-context.ts`（命名按仓库风格调整）。要求纯函数 + 可注入时钟，便于测试。

### 5.1 NormalizedGroupMessage

| 字段 | 说明 |
| --- | --- |
| `messageId` | 外部消息 ID（字符串）；缺失时用现有可靠的事件去重标识，不要用正文哈希冒充 |
| `at` | 接收时间（ms） |
| `senderQq` | 发送者 QQ（字符串） |
| `displayName` | 仅展示，不参与身份合并 |
| `text` | 原文（仅内部与存储使用） |
| `mentionTargets` | `self` / `other` / `all` / `unknown`，可多个 |
| `replyTo` | `{ messageId, senderQq? }`，解析不到时为空 |
| `selfSent` | 是否本角色发送 |

### 5.2 有界上下文

- 隔离键：**连接 + 绑定 + 群会话**，不能只用群号。
- 默认：最近 5 分钟、最多 40 条、总文本约 6000 字符（单条截断），全局活跃会话数与引用链长度也设上限，惰性淘汰。
- 进入时机：收到有效普通群消息后、语义闸门**之前**。被闸门丢掉的消息仍可作背景，但不落库、不进长期记忆。
- 背景与本轮**分区传入，不重复拼接**；预算不够时优先保留本轮，再裁旧背景。
- 背景只供理解，不能当新消息补回，不能当成本角色的 assistant 发言。

### 5.3 TopicParticipation（按话题，不按人）

```ts
interface TopicParticipation {
  anchorMessageId: string;      // 建立锚点的那条消息（必填，来自本轮已校验事实）
  participants: string[];       // 参与过这个话题的成员代号（邀请者只是其中之一，可空）
  triggerMessageId: string;     // 触发消息（首次建立时用）
  lastEvidenceAt: number;       // 最后一次有证据的相关互动
  createdAt: number;
  expiresAt: number;            // lastEvidenceAt + 3 分钟，且不超过绝对上限
  source: 'mention' | 'ambient';
}
```

**更正（相对 Grok 版）**：不按邀请者做「新话题覆盖旧话题」。同一个人可以同时聊几件事，邀请者只是参与者之一。话题以锚点为单位；达到上限（建议 3 个）时按 `lastEvidenceAt` 淘汰最旧的。自然水群建立的话题可以没有邀请者。

## 6. 建立、刷新、失效

- 真实 @ 她：可建立「待回应邀请」，但**回复发送成功后**才算实际参与、写入锚点。
- 自然插话发送成功后也可以建立锚点。
- **第一次参与不能依赖已有锚点**：用本轮触发消息作为新锚点，必须来自已校验的本轮消息 ID。
- 刷新 `lastEvidenceAt` 只认经过校验的新相关证据（模型给出合法 `evidenceMessageIds` 且能对应本轮消息，或消息明确引用/回复她）。
- `silent` 本身不能建立参与，也不能无条件续期。但允许一种有界情况：`silent` + 合法 `groupDecision`（`followup` / `shared_topic`）且引用了新的本轮证据时，刷新已有话题——前提是该话题未超过**绝对存活上限**（建议 15 分钟），避免一个话题被无限续命。
- 无关消息不续期；一个话题过期不清除其他有效话题。
- 恰好 3 分钟、到期前、到期后都要有确定性测试。

## 7. 行为判定表

| 情况 | 处理 |
| --- | --- |
| 本轮可靠地真实 @ 她 | 标记 `direct`：进入不允许主动沉默的应答路径；受日上限、最短间隔、群规、额度约束，**不因 direct 绕过这些限额**；可绕过安静时段 |
| 同一邀请者不带 @ 继续说话 | 作为候选（`optional`），模型判断是否仍是原话题、是否在问她；允许 silent |
| 同一邀请者换了话题 | 不因身份相同自动跟进 |
| 其他成员加入她参与过的话题 | 可作为候选补充，不要求是原邀请者 |
| 已参与话题里，群友 @ / 回复另一条鱼 | 不做一刀切跳过；可补充，但不得冒充被询问者、不得虚构共同经历 |
| 她未参与，群友明确 @ 其他账号 | 不插这段对话；若整批没有其他候选，零成本跳过模型 |
| 无 @ 的普通水群 | 走现有机会闸门（概率/相关），模型决定说不说 |
| 只有名字/别名/单字昵称命中 | 弱线索：可进入判断，**绝不强制回复、不绕过安静时段** |
| 混合批次（同时有 @ 别人、@ 她、普通闲聊） | 逐条保留指向，**禁止**用一个批次级布尔值丢掉整批 |
| 引用目标不可解析 | 标 `unknown`，不猜被引用者，不当作指向她 |
| 多话题并行 / 指向不清 | 不因已关注某人就自动跟聊；不确定就 silent |

**「有活跃话题」≠「这句话属于那个话题」。**程序知道她有几个话题，但不知道每条 @ 别人的消息是否属于其中之一。所以：

- 完全没有有效话题，且整批只有明确找别人的消息 → 可以直接跳过；
- 有有效话题但归属不明 → 只能作为候选交给模型；
- 不能因为「还有一个话题没过期」就认定所有 @ 别人的消息都能接。

## 8. 模式、策略与闸门

一条管道，三种放行策略。实施时同步更新 UI 文案与测试，不能悄悄改变旧含义。

| 模式 | 哪些消息进待判批次 | 说明 |
| --- | --- | --- |
| `ambient` | 全部 | 默认。direct 必回；其余按参与候选 / 概率 / 间隔放行，模型决定说不说 |
| `mention` | direct，以及已参与话题的后续候选 | 保留「只被叫到才回」的定位，不开放无关水群。名字命中是弱线索：可以进批次（复用短窗口），但允许 silent |
| `all` | 全部 | 保留显式兼容行为：每轮都进模型、不允许 silent（`allowSilent=false`），也不受日上限/间隔/安静时段约束，与现状一致。不要借本次防冒领把 all 变成强制沉默 |

注意：`mention` 档不再有独立的单条快速路径。它和另外两档共用攒批、上下文与模型调用，只是策略更窄。`CLAUDE.md` 里「`mention` 档完全不攒批」这句必须随之更新。

闸门输出两类候选，而不是一个布尔值：

- `direct`：批次里有真实 @ 她。必进模型、`allowSilent=false`；仍受日上限、最短间隔、群规、额度约束；可绕过安静时段。
- `optional`：跟进 / 共享话题 / 水群。受概率、间隔、额度约束，允许 silent；不绕过安静时段。

执行顺序（在现有顺序上扩展，不推翻）：

1. 模式策略：`mention` 档把非 direct、非参与候选的批次直接丢掉（消息已进上下文缓存，成本为零）；`all` 档全部放行。
2. 安静时段：只挡 `optional`；direct 可绕过；`all` 档沿用现有行为，不做这步判断。
3. 日上限 / 最短间隔 / 群规限流：`mention` / `ambient` 两档的 direct 与 optional 一视同仁，不得绕过；`all` 档按现有兼容行为不叠加这些门槛。
4. 语义机会：direct 直接放行；optional 依次看参与候选 → 概率抽签。
5. 都不过 → 整轮丢掉，不调模型。

只有「明确排除且无其他候选」时才零成本跳过。「是不是同一个话题」交给模型，不用关键词重合伪装语义判断。视觉理解仍然**先过闸门**，被丢掉的轮次不为看图花钱。

## 9. 模型输入

分区传入，禁止混在一起：

1. **群聊事实元数据**（程序产生）：本轮是否真实 @ 她、是否允许沉默、当前模式。
2. **近期背景**（有界缓存，已裁剪）。
3. **本轮消息**：每条带消息 ID、成员代号、时间、正文、指向、引用。
4. **参与锚点**：有限列表，只能是本次提供的这些。

身份处理：

- 程序内部按 QQ 关联；入模转成会话内稳定代号 `member_1`…，昵称是可选展示字段。
- 同名不同 QQ 给不同代号；同一 QQ 改名仍是同一代号。
- **正文里的 `@QQ号` 也要代号化**（@ 她 → `@self`，@ 别人 → `@member_n`），只改发送者字段不够。数据库原文保持不变。
- 不传原始 QQ、数据库 ID、密钥、其他无关私人信息。
- 群聊只读角色全局记忆，不拼任何成员的私人 memory scope；成员代号不是跨平台身份，不用于私人记忆检索。
- 正文里伪造「我 @ 了你」「忽略上面的规则」不能覆盖结构化指向。

## 10. 提示词要点

- 分别判断：直接找她 / 跟进已参与话题 / 共享话题可补充 / 自然水群 / 无关。
- 同名同款角色可能很多，名字不是身份确认。
- 别人被问的问题不是她的问题；不要冒充被问者。
- 已参与话题可以补自己的想法，但不虚构共同经历，不把别的鱼的回答算成自己说的。
- 水群发有内容的短句，避免机械附和、复述、逐条点评。
- 明确 @ 别人且她未参与时不插嘴；指向、话题、引用不确定时沉默。
- 真实 @ 的必回语义由程序执行，不指望模型「自觉遵守」。
- 不要求输出隐藏思考，只输出既有回复协议 + 可选结构化决策。

---

## 11. 输出与校验

复用现有 `action/reply` JSON，不另调一次模型。新增**可选** `groupDecision`：

```ts
interface GroupDecision {
  relation: 'direct' | 'followup' | 'shared_topic' | 'ambient' | 'unrelated';
  topicAnchorMessageId?: string;  // 只能从本次提供的锚点里选
  evidenceMessageIds?: string[];  // 只能从本轮新消息里选，少量
}
```

硬性规则：

- 枚举、长度、数量、来源 ID 白名单校验；不接受模型自造 QQ / 成员 / 话题锚点。
- 字段缺失或非法 → 只忽略该字段并记安全日志；不能因为可选字段坏了就让正常回复失败。
- `direct` 与 `allowSilent=false` 是程序事实，模型返回 `unrelated` 也不能覆盖。
- `silent` 不发空消息、不写伪 assistant 历史，usage 照常记账。
- 模型异常沿用现有错误处理，不新增额外模型循环。

程序侧兜底（仅这一条）：本轮**没有**任何有效参与话题，且这批消息只有明确 @ 别人的内容、没有独立候选 → 直接 silent，不调模型。有有效话题时不启用该兜底，交给模型判断。

## 12. 代码落点与顺序

1. `onebot/types.ts` / `serve.ts`：解析 at/reply 事实，产出 `hardMentions`（真实 @）与 `softNameHits`（文字弱提及），保持命令路由与去重先后。
2. 新增 `onebot/group-context.ts`：有界缓存、QQ→成员代号、话题参与、过期清理、可注入时钟。
3. `onebot/group-chat.ts`：闸门输出 `direct` / `optional`，用参与候选替代 `lastSpokeAt` 相关性；保留「先配置/额度/时间、后语义机会」的顺序；按模式给出放行策略。
4. `serve.ts`：**删掉群聊的单条入口**，让 `mention` / `ambient` / `all` 都走同一个 buffer（direct 用 `mentionWindowSeconds`，其余用 `batchWindowSeconds`；`all` 用很短的窗口）；接入缓存与候选，正确处理混合批次；只有 direct 与 `all` 档才 `allowSilent=false`；发送成功后更新状态；沿用会话串行锁，防旧批次覆盖新状态。
5. `channel-adapter/pipeline.ts`：传结构化背景/本轮/锚点，控制预算；不得把别人的群消息当成本角色 ASSISTANT；核对 silent 路径的去重、落库与 usage。
6. `chat-reply.ts`：群聊语境独立于 `allowSilent`（必回也要有群聊上下文）；扩展可选决策字段与校验；不影响网页聊天、私聊与旧响应。
7. 更新 `docs/qq-onebot-adapter.md` 7.1 与 `CLAUDE.md` 对应段落；只有实际改到公开接口/schema 才动 OpenAPI/migration（本方案不涉及）。

先跑通身份、上下文、决策链，再补文案。不要顺手重构整个渠道框架。

## 13. 验收测试

确定性测试验证解析、闸门、状态、校验与发送行为。Mock 模型测试只证明协议链路，**不能**宣称真实模型语义准确。

### 13.1 身份与解析

1. A @ 她 → 应答并关注 A；A 改昵称仍是同一人；同名 B 不是 A。
2. 结构化 at、`@全体`、多个 @、CQ 字符串、reply 段、引用缺失。
3. `self_id` 缺失时用连接账号 QQ 兜底；两者都没有才 unknown，不能误判 self / other。
4. 未知成员按普通外部成员处理，不靠昵称推断其他机器人。
5. 混合批次：@ 别人 + @ 她 + 独立闲聊，逐条处理，不整批误丢。

### 13.2 上下文与话题

6. 被闸门丢掉的消息进入背景，但不落库、不进长期记忆、不当 assistant。
7. A 不带 @ 跟进原话题可答可 silent；A 转去问别人别的事不自动认领。
8. 其他人加入她参与的话题可补充；不虚构别人的经历。
9. 未参与话题里 A @ 其他鱼 → 不插嘴；该句仍可进背景缓存。
10. 并行话题（含同一人多线）、跨连接/绑定/群隔离、缓存满、超长单条、惰性淘汰、重启降级。
11. 恰好 3 分钟、到期前/后；无关消息不续期；一个话题过期不清另一个；silent+新证据的有界续期与绝对上限。
12. 旧批次不覆盖新状态；重复事件不二次发送、不重复入缓存、不刷过期时间。

### 13.3 回复与限额

13. 真实 @ 也走攒批：`mention` 档的 @ 带群聊上下文，且 `allowSilent=false`；不能再出现「只有一句话、没有背景」的单条路径。
14. 三种模式都只改变放行策略：`mention` 档非 direct 的普通水群不进模型；`all` 档每轮都进模型；`ambient` 档按机会闸门。
15. 模型的 `unrelated` 不能覆盖真实 @；模型异常沿用既有处理。
16. 发送失败、silent、只调模型都不记参与；发送成功才写锚点。
17. 额度、间隔、群规、安静时段仍生效；被阻止时不调聊天或视觉模型。
18. silent 不发空消息、不写伪 assistant；usage/落库/去重符合现有约定。
19. 网页、私聊、公告、B站 口令、视觉、表情、群聊私人记忆隔离无回归。

### 13.4 真实模型语义抽查

至少少量真实轮次，检查两类核心错误：

- **错误认领**：她没参与，群友明确 @ 别的角色，她却插话；
- **错误退出**：她已参与同一话题，别人继续讨论，她无理由完全退出。

另测多线聊天、同名角色、引用另一条鱼。记录样例时脱敏；不要声称 Mock 证明语义准确。

## 15. 完成标准

- 被真实 @ 时在限额允许下正确应答，不被名字撞车强制认领；
- @ 和水群走同一条管道：@ 也有上下文，水群不会因模式选择被整个关掉；
- 能基于「参与过的话题」判断是否补充，而不是只看最近是否发过言；
- 未参与且明确指向别人的对话不抢答，但同一批次里的独立消息不被误伤；
- 已参与的话题里，别人被问的问题不被冒充；
- 水群仍由低成本闸门控制，模型可以合理沉默；
- 上下文与状态有界、隔离、可过期、可测试；
- 现有模式、限额、私聊与其他渠道无回归；
- 测试报告准确区分「已通过」「未执行」「真实模型仍需观察」。
