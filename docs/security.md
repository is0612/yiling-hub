# 安全与隐私规范

## 1. 登录会话与阶段性鉴权

首版以单管理员模式为目标，但只要后台 API 可被网络访问，就必须进行服务端鉴权。当前版本可以实现的范围是：用户名 + 密码登录、服务端会话、服务端资源授权；不包含多用户注册、组织与角色权限。

已实现（2026-10-24）：

- **会话存储**：`sessions` 表保存会话，数据库只存浏览器会话令牌的 SHA-256 哈希；令牌本身只存在于 HttpOnly Cookie 中。会话有过期时间、撤销时间、最近使用时间和可选的来源地址哈希（同样是哈希，不存原始 IP）。
- **Cookie 属性**：`yiling_session`，`HttpOnly`、`SameSite=Strict`、`Path=/`，`NODE_ENV=production` 或 `YILING_COOKIE_SECURE=true` 时带 `Secure`。有效期为 `AUTH_SESSION_TTL_HOURS`（1–720，默认 12）。
- **密码存储**：scrypt（`scrypt$salt$digest`），校验使用恒定时间比较；账号不存在时也执行一次占位哈希校验，避免通过响应时间枚举用户名。
- **登录限流**：失败记录写入 `login_attempts` 表，同一用户名 15 分钟内失败 5 次、或同一来源地址失败 20 次后返回 429；登录成功会清除该账号的失败记录。
- **CSRF**：所有 `/api` 请求校验 `Origin` 与 `Sec-Fetch-Site` 必须与当前 Host 一致；写操作额外依赖 `SameSite=Strict`。浏览器跨源/跨站请求返回 403。没有这两个头的非浏览器客户端（脚本、服务端调用）仍可访问，但同样需要有效会话。
- **未登录语义**：业务接口返回 401。携带失效/已撤销 Cookie 时**不会**静默回退到本地开发身份，必须重新登录。
- **本地开发回退**：仅当 `import.meta.dev` 为真、`YILING_LOCAL_API_ENABLED=true`、`YILING_ALLOW_DEV_OWNER_BYPASS` 未设为 `false`、且 Host 是 localhost/回环地址时，才以 `DEV_OWNER_ID` 身份运行。生产构建不满足 `import.meta.dev`，因此不存在该通道。

仍待完成：密码修改与重置流程、多用户与角色权限、会话管理界面（查看/踢出其他设备）、登录审计日志、以及部署侧的 HTTPS 与反向代理信任配置。

## 2. 服务端 Token

内部 Adapter 或可信服务之间可以使用服务端 Token。Token 只能存在服务端环境变量或受控的凭据存储中：
- 不得放入 `NEXT_PUBLIC_*` 变量。
- 不得嵌入前端 bundle。
- 不得提交到 Git。
- 不得写入普通日志。
- 应支持轮换和撤销。

不要让浏览器直接携带一个固定的管理员主密钥访问所有后台接口。

## 3. 数据隔离

- 每个查询、更新、删除都要在服务端验证角色所有权和记忆范围。
- 角色全局记忆与用户私人记忆严格分开。
- 不允许用户通过修改 URL、ID 或请求参数访问他人数据。
- 跨平台账号关联必须经过验证；不能依据昵称自动合并。
- 消息与快照的来源关联不得绕过范围校验。

## 4. 凭据和配置

- 真实 `.env` 不提交到 Git。
- 仓库只提交不含秘密的 `.env.example`。
- 平台凭据优先加密保存或放到专门的 Secret Store。
- 角色模型 API Key 使用 AES-256-GCM 加密后保存在角色配置中；加密密钥自动生成在本机被 Git 忽略的 `.data/credentials-encryption.key` 文件。
- 聊天模型请求只能将角色设定、对话和已检索上下文等明确白名单字段序列化到提示词正文；API Key、模型服务地址及连接参数不得进入提示词正文，API Key 仅通过服务端授权请求头发送。
- 备份或迁移数据库时必须一并安全保管该加密密钥；密钥文件丢失后，已保存的 API Key 将无法解密，需要重新录入。
- 数据库连接串、API Key、Cookie 不得回显给用户或写入错误日志。
- 生产与本地使用不同凭据。

## 5. 记忆与日志

聊天记录、快照和备份都可能包含敏感信息，应按敏感数据管理。
- AI 提炼会把当前周期选取的消息片段、角色范围和活动长期记忆发送到配置的模型服务；使用前应确认供应商的数据保留、训练使用和区域处理条款，并告知/征得所需用户同意。
- 模型只接收服务端到服务端请求，密钥不进入浏览器；请求正文不得写入应用日志。模型输出中的来源 ID 必须通过本地原始消息白名单验证后才能写入记忆。
- CI 会在数据库中预置一条仅存在于 `USER_PRIVATE` 范围的哨兵记忆，并让模拟模型在该内容进入角色全局对话上下文时直接失败，以防止检索改动意外跨范围泄露。此测试只验证隔离边界，不代表私人记忆聊天能力已经开放。
- 只收集产品所需的数据。
- 明确原始消息保留期限和删除规则。
- 快照保留与原始消息清理是不同策略。
- 普通运行日志优先记录 ID、状态和错误摘要，不默认记录完整聊天正文。
- 支持用户要求的记忆删除，并评估关联快照、来源关联与备份中的数据处理。
- 备份应存放在源服务器之外，必要时加密并限制访问。
