# 开发阶段与验收标准

## Phase 0：规格与数据契约
**交付：** 产品方案、记忆规则、逻辑数据模型、Prisma Schema 草案、OpenAPI 3.0 YAML、安全规则、迁移说明。

**验收：**
- 角色、渠道、消息、记忆范围、长期记忆、快照版本和任务之间关系明确。
- API 具有方法、路径、参数、成功响应、错误响应与鉴权要求。
- 周期边界、修改周期、手动快照、版本化、重试和补处理规则没有歧义。
- 本地环境、备份与恢复方案明确。

## Phase 1：前端 Mock
**交付：** 首页概览、角色列表、记忆驾驶舱、快照档案、周期设置、渠道占位页、任务监控 Mock。

**验收：**
- 使用已确认的浅色极简视觉风格。
- Mock 数据遵守 API 契约。
- 加载、空状态、错误状态和禁用状态有清晰呈现。
- Mock 任务被明确标识，不假装实际执行。

## Phase 2：基础数据库/API
**交付：** PostgreSQL、Prisma Schema/migrations、Seed、角色 CRUD、消息与记忆基础 API、快照查询、周期设置 API、单管理员登录和服务端鉴权。

**验收：**
- 数据持久化；迁移可重复用于新环境。
- 未授权请求被拒绝。
- API 进行服务端资源与记忆范围检查。
- 错误格式一致。
- 备份和恢复流程在本地验证。

**已实现（2026-10-24）：** 单管理员登录（scrypt 密码校验）、PostgreSQL `sessions` 表会话（只存令牌哈希）、HttpOnly/SameSite=Strict/生产 Secure 的 `yiling_session` Cookie、登录限流、`/api` 同源/跨站校验、所有业务接口从会话取身份并在未登录时返回 401。管理员可在系统设置页修改密码（改密后注销其他所有设备）并查看/撤销登录设备。本地开发保留受限回退（见 `docs/security.md`），生产构建没有该通道。回归测试：`yarn test:auth`、`yarn test:auth-db`。仍待完成：多用户与角色权限、忘记密码的重置流程、登录/登出的完整审计视图。

## Phase 3：周期记忆引擎
**交付：** 独立 Worker、调度、任务表、快照生成、来源关联、长期记忆更新、版本化、重试、补处理、任务监控。

**必须先写并运行测试：**
- 默认 8 天周期边界正确。
- 时区转换正确。
- 周期修改按下一周期生效。
- 手动快照不重置自动计划。
- 重复执行不会重复创建当前快照。
- 并发 Worker 不会重复领取并写入同一任务。
- 模型成功而数据库写入失败时，任务不会被标为成功。
- 停机错过周期后能补处理。
- 重新生成创建新版本。
- 无活动周期跳过并推进计划。
- 用户私人记忆隔离。
- 自动 AI 快照重新提炼会在同一逻辑快照下创建新版本，保留历史版本，并把重新提炼提出的长期记忆变化作为审核建议，不自动应用。
- 等待中的任务可取消；周期快照生成、快照重新提炼和原始消息清理任务可对失败、待重试或已取消状态手动重新入队，并保留审计记录。
- 原始消息保留期支持永久、30/90/180 天；新角色默认永久保留，有限期限需要单独确认授权；旧角色历史有限保留值不自动触发删除。
- 清理任务只删除截止时间之前的原始消息；如果更早快照仍待处理或失败，必须延后清理。
- 删除原文、完成清理任务和写入审计记录处于同一数据库事务。
- CI 验收真实删除数量、近期消息保留、永久保留不排队、清理任务取消/重试和失败快照保护。

## Phase 4：记忆检索与模型回复
**当前已实现第一段（待本机真实模型验证）：**
- 新增角色 AI 对话页面，可创建/继续会话，用户消息与回复持久化到 PostgreSQL。
- 每次请求加载最近 20 条对话消息，并通过中英文关键词相关性排序检索最多 8 条活动长期记忆、4 份当前快照；检索会过滤常见提问意图词、优先匹配短语，并按当前候选集合中的词项稀有度调整权重。它仍是词法检索，不等于向量语义检索。
- 模型回复携带它声称使用的来源 ID；服务端按本轮提供的候选 ID 白名单过滤后保存来源详情，前端可展开查看来源。
- 新增检索、角色模型参数校验单元测试和本地模拟模型端到端冒烟测试。
- 会话管理支持关键词搜索、重命名、可恢复归档和 Markdown 导出；归档/恢复/重命名动作写审计日志，归档会话禁止继续写入新消息。
- 对话检索按身份隔离范围：始终读取角色全局记忆，另加当前用户自己的私人记忆范围；其他人的私人记忆、未验证外部身份的范围、未知范围类型一律不参与检索。记忆来源带 `character` / `private` 语义标签，前端以「私人」标签区分，导出 Markdown 也会标注来源范围。会话本身仍归属角色全局范围。
- 每个角色可在网页里单独填写 API Base URL、API Key、模型名称、温度和最大输出 Token；支持保存后测试连接，聊天与周期记忆 Worker 共用该角色的 API 设置。AI 回复支持一键复制。
- API Key 以 AES-256-GCM 加密保存。自动生成的本地密钥位于被 Git 忽略的 `.data/credentials-encryption.key`，数据库迁移或备份时必须一起保管；丢失此文件后需要重新录入 API Key。
- 自动快照可按原周期排队重新提炼；新版本保留旧版本，重放历史时的长期记忆变化只供审核。后台任务支持安全取消和手动重新入队。

**仍待完成：** 本地真实模型 API 验证、更强的语义检索/重排、正式登录后的真实多用户身份上下文（当前私人记忆范围以本地开发用户身份验证），以及相关公开部署安全审查。

**阶段验收：** 能返回与问题相关的记忆；不把无关历史全部注入上下文；不跨用户泄露私人记忆。当前已启用角色全局记忆与当前用户私人记忆上下文，跨用户隔离由 `yarn test:chat-private-memory` 与 `yarn test:chat-private-memory-db` 覆盖。

## Phase 5：外部渠道
**交付：** 至少一个真实平台 Adapter，完成事件接入、去重、记忆检索、生成回复、持久化和发回平台。

**验收：** 完整链路可运行；连接失败可观察；重复事件可幂等处理；平台权限和规则已检查。

## Phase 6：部署和扩展
**交付：** HTTPS、配置管理、备份恢复演练、监控、磁盘告警、日志轮转、数据删除策略与后续扩展说明。

**验收：** 恢复测试成功；公开接口完成鉴权；数据库不公开暴露；关键任务状态可观察。

## 每个任务的交付格式

实现一个阶段中的具体任务后，报告：
1. 修改的文件；
2. 完成的功能；
3. 执行过的检查及真实结果；
4. 未实现或未验证的内容；
5. 建议的下一步。

不要在没有运行测试的情况下声称测试通过。
