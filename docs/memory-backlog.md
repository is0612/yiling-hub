# 忆泡待办清单

> 状态：进行中（2026-10-31 建立）
> 约定：按优先级从上往下做；「阻塞」表示依赖上一项完成后才有意义。

## P0 · 分段抽取（下一个大件）

**问题**：现在按「每会话 80 条 / 全天 250 条 / 进模型前截 120 条」取原文。实测一天 3381 条时，模型只看到约 3.5%，事件密度被稀释，大群会把其它会话挤掉。

**方案（已讨论，未定稿）**：锚点切片 —— 以「她发过言 / 有人 @ 她 / 叫她名字 / 出现约定类信号」为锚点取前后窗口，合并重叠片段，再逐段判断有没有事件。

**待定**：覆盖率预期（只记她参与的 vs 群里大事也记）、片段是否落库、每群每日调用上限。

## P1 · 参与者身份引用（阻塞：P0）

**问题**：`MemoryEvent.participants` 是模型抄来的显示名（含 `member_3` 这类代号）。昵称一改就对不上，两个群都叫「群友」会混，查不了「和小关都经历过什么」。

**现状**：只能显示，不能可靠检索到人。

**方案**：加结构化引用，展示层仍用名字。

```json
"participants": [
  { "kind": "self" },
  { "kind": "owner" },
  { "kind": "external", "platform": "qq-onebot", "externalId": "3692476496", "displayName": "小关" }
]
```

- 引用**从证据消息的 `authorOpenId` 推导**，不靠模型编；
- `self` = 她自己发的消息，`owner` 看 `isOwner`；
- 历史忆泡从 `sourceMessageId` / 证据消息回填；
- 跨平台同人合并仍必须走验证绑定，**不能靠同名自动合并**。

**代价**：`MemoryEvent` 加列（迁移）、提取时写入、DTO 与前端展示跟着改、历史回填脚本。

**为什么排在 P0 后**：现在一天只抽到 5–6 条，先把「记全」做对，再谈「记准到人」。

## P1 · 按原因分层保留

`storedReason` 已经落库（`replied` / `silent` / `mentioned`），但清理仍只有「按天数」一刀切。

- `context`（纯上下文行）：7 天
- `mentioned` / `replied`：30 天
- 忆泡 / 快照：永久

注意：现有角色「小鲸鱼i」的 `rawMessageRetentionDays` 仍是 `null`（永久），新建角色才是 30 天。

## P2 · 快照改读当天忆泡

8 天周期快照现在仍从原文重抽一次，和按天的忆泡是两套逻辑、两套配额。长期应改成「读该周期内已有的忆泡汇总」，否则同一件事会被两套规则分别判断。

## P2 · 参与者硬过滤 / 取首聚合

- 按参与者过滤忆泡（「和小关的所有事」）依赖 P1；
- 「第一次见到某人」这类聚合查询需要「取首」模式，现在只有时间区间 + 关键词。

## P3 · 忆泡来源回写 `usedSources`

现在只存一条 `sourceMessageId`，一条忆泡由多条消息支撑时，后几条的来源丢失。
