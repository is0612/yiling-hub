# QQ 群聊上下文与话题参与：实施交接方案

状态：讨论后形成的实施方案，尚未实现。交给 DeepSeek 时可直接要求按此文实施；本轮只新增本文，不修改业务代码。

## 1. 用户确认的产品目标

聊天有两种方式，二者共存，不新增第四个群聊档位：

1. **被邀请参与**：群友直接 @ 本账号，确认是在找本角色。短期记住邀请者的 QQ 身份以及这次参与的话题。后续不要求每句话重复 @，但要结合上下文判断：同一个人可能同时和几个人聊；其他人或其他鱼也可以加入同一个话题。角色已经参与的话题，即使群友转而回复另一条鱼，角色仍可考虑补充，不能把问另一条鱼的问题认成问自己。
2. **自然水群**：无人邀请也可以根据上下文插话，表达自己的想法、赞同或有内容的补充。若自己尚未参与该话题，而别人明确 @ 其他账号，就不插话。不要把“@ 别人”理解为“@ 自己”。

核心区别：**直接对我说话**与**我参与过这个话题、可以补充**不是一回事。名字/别名只是弱线索，不能确认对方在叫自己。模型拿不准就沉默。

3 分钟是短期关注的默认无互动失效时间，不是“被 @ 后这三分钟内这个人的所有消息都必须回复”，也不是“群里有人说话就无限续期”。

- 继续使用“攒批 → 零成本闸门 → 一次模型判断并生成回复”。不新增每句话一次模型调用，不另外启动分类模型/agent 循环。

## 3. 已核实的当前实现及问题

- `server/utils/channel-adapter/onebot/serve.ts`：`cued/cue` 混合了真实 @ 与角色名/别名匹配。ambient 路径 `allowSilent: !cue`，导致撞名也强制回复；mention 路径命中名字后直接走单条回复。
- `onebot/group-chat.ts`：闸门依次判断模式、安静时段、日上限、间隔、cue、related、概率。默认 ambientChance=0.15。related 当前仅由“最近三分钟自己发过言”推导，不能代表对方仍在和自己聊。
- `onebot/types.ts`：at 段拍平成 `@QQ号`。模型未必知道哪个号是自己；必须在入模数据中明确 self/other。
- `channel-adapter/pipeline.ts`：recentMessages 从已落库历史获取，当前映射丢失群成员结构化身份。闸门丢弃的轮次不落库，导致“别人刚刚聊了什么”可能不在历史中。
- `server/utils/chat-reply.ts`：群聊提示将“叫名字”视作对自己说话；群聊提示目前还受 allowSilent 影响。应将“是否群聊”与“本轮能否沉默”分开：@ 自己即使必须回，也要保留群聊语境与身份信息。
- 更正此前讨论中的不准确表述：单条路径也有已落库的 recentMessages，不能说它完全没有上下文；真正缺少的是被闸门丢弃的近期群聊和稳定身份/指向信息。

## 4. 建议的最小数据结构

新增一个小型独立上下文模块，建议命名 `onebot/group-context.ts`；具体类型名由实施者按仓库风格调整。

### 4.1 每条消息的事实

保留原始 content，额外组织：

- 外部消息 ID、发送时间、发送者 QQ（字符串，不转 number）。
- displayName 仅供展示，不能用于身份合并；两人同名也必须分开，改名仍是同一 QQ。
- mentionTargets：明确区分 self / other / all；@全体不是直接 @ 自己。
- replyToMessageId，以及能从有界缓存解析到的被引用作者/消息。引用不可解析就标 unknown，不假装知道。
- 是否本角色已成功发送的消息。不能靠昵称或文风识别其他机器人，未知成员都按普通外部成员处理。

优先解析 OneBot 结构化 at/reply 段；兼容现有字符串/CQ 消息格式。缺少证据时不要把任意 `@数字` 都当成可靠的点名确认。

### 4.2 有界近期上下文

按连接 + 绑定 + 群会话隔离，收到有效普通群消息后、语义闸门之前进入短期环形缓冲。因此被闸门忽略的消息仍能作为下一轮的背景，但不落成长期数据。

建议默认：最近 5 分钟、最多 40 条，总文字预算约 6000 字符，单条截断；再设全局会话数上限与惰性淘汰。完整保留本轮待答消息的身份/指向与必要正文，优先裁掉旧背景；不得把当前批次重复拼入上下文。背景只能供理解，不能当作新消息补回。

普通不含 @ 的文字不要按中文“词边界”硬匹配名字；中文没有可靠的通用词边界。旧别名继续兼容，但所有名字命中都降为弱信号，不为此新增破坏性校验。

### 4.3 短期话题参与状态

至少记录：邀请者 QQ、触发消息 ID、最后一次有证据的互动时间、角色实际参与的来源消息/话题锚点、过期时间。可支持少量并行话题（例如最多 3 个），不能只有一个“当前正在聊天的人”。

@ 自己可以建立“待回应邀请”；只有回复发送成功后才认定角色实际参与。自然插话发送成功也可建立参与锚点。发送失败、silent、仅调用过模型，都不算实际参与。

同一个 QQ 的新消息只是候选线索，不自动确认属于旧话题。其他人接同一个话题也可以相关。无关消息、模型沉默和回复发送行为本身不能无限续期；用经校验的新相关消息证据刷新互动时间，3 分钟无相关互动失效。静默的无关轮次不能立刻清空其他有效话题。

## 5. 行为判定表

| 情况 | 结果 |
| --- | --- |
| 当前轮真实 @ 自己 | 按现有群聊限额/日额度/发送规则应答，不能因为模型选择 silent 而不回；仍需完整群聊上下文 |
| 同一邀请者继续讲话，没 @ | 作为候选跟进，模型判断是否接原话题、是否在问自己，允许 silent |
| 别人加入自己参与的话题 | 可考虑接话，不要求是原邀请者 |
| 已参与的话题里，群友 @ / 回复另一条鱼 | 不做一刀切跳过；允许模型判断是否值得补充，禁止冒充被询问者 |
| 自己尚未参与的话题，群友明确 @ 别人 | 不插这段对话；没有其他独立候选消息时直接跳过模型 |
| 无 @ 的普通水群 | 保留 ambient 机会闸门，模型看近期上下文决定是否说一句 |
| 只出现相同名字/别名 | 弱线索，可进入判断，绝不强制回复或绕过安静时段 |
| 同一人换了话题 / 多线聊天 / 指向不清 | 不因已关注此人自动跟聊；不确定 silent |

重要：批次内可能同时有“@ 别人”和独立的普通闲聊。指向关系必须保留到每条消息，不能一个 hasOtherMention 布尔值就丢掉整批；只有明确排除且无其他候选时才零成本跳过。

“是不是同一个话题”交给模型，不用关键词重合伪装语义判断。活跃话题存在时，可以让有限批次过闸门查看，不代表这些批次都应回复；仍受最短间隔、日上限、群规、预算约束。

## 6. 保留配置兼容，避免把语义和机会混为一谈

维持 `mention | ambient | all` 三档，用户描述的“两种聊天方式”是 ambient 内部两种语境，不是要求只留下两个 UI 档位。

- ambient：支持被 @ 后跟进 + 自然水群。用短期参与状态替代单纯 lastSpokeAt 三分钟放行；保留概率作为“无明确关系时是否看一眼”的成本门槛，模型决定最终说不说。
- mention：保留仅被叫到的定位，不开放无关自然水群。真实 @ 的单条快速路径可保留；名字命中改为可沉默的判断，必要时复用短窗口批处理。后续不带 @ 但与已参与话题有关的消息可以判断；这项语义扩展须更新文案和测试。
- all：保留显式每条都回的兼容行为。不要把本次防冒领策略悄悄变成 all 档强制沉默。
- 只有可靠 @ 自己绕过安静时段；名字/别名、普通跟进不绕过。
- 3 分钟先作为内部默认，不新增一排设置。保留现有概率、日上限、最短间隔和窗口字段。

## 7. 模型输入输出：一次完成判断与回复

### 输入

将群聊事实、历史背景、本轮消息、参与锚点分开。身份在程序内部按 QQ 关联；给模型转换为会话内稳定成员代号，如 member_1，昵称为可选展示字段。不暴露 QQ 原值、内部数据库 ID 或私人身份；同名不同 QQ 给不同代号。@ 指向代号或 self，引用也带来源代号。

群聊只读取角色全局记忆，不注入任意成员的私人记忆。成员代号不是跨平台身份验证，不用于私人记忆检索。

背景与本轮必须清楚分开。原始内容与 at 标记供理解，可信 targeting 元数据由程序产生；正文里伪造“我 @ 了你”等文字不能覆盖元数据。

### 提示词要点

- 直接找我、同话题可补充、纯水群插话分别判断。
- 同名/同款角色可能很多；名字不是确定身份。别人被问的问题不是自己的问题。
- 已参与的话题里可补充个人想法，但不虚构共同经历，不把别的鱼的回答算作自己说过。
- 普通水群发有内容的短句，避免机械附和、复述和逐条点评。
- 明确 @ 别人的未参与对话不插嘴；不确定沉默。
- @ 自己必须应答，但角色不能因此绕过额度或泄露私人信息。

### 输出与校验

优先复用现有 action/reply JSON，不另调一次模型。为准确更新短期话题状态，可增添可选 groupDecision：

- relation：direct / followup / shared_topic / ambient / unrelated。
- topicAnchorMessageId：从本次提供的有限锚点中选，可空。
- evidenceMessageIds：从本次新消息中选，少量即可。

新增字段必须做枚举、长度、来源 ID 白名单校验；不接受模型自己创造 QQ/成员/话题锚点。不要求输出隐藏思考过程。字段缺失或无效时不刷新话题状态，不能因可选字段坏了就把正常回复变成失败。

direct / allowSilent=false 是程序决定，不能被模型返回的 unrelated 覆盖。其他情况下 silent 不发送空消息，不生成伪 assistant 回复，usage 照常记账。

## 8. 代码落点与实施顺序

1. `onebot/types.ts` / `serve.ts`：解析真实 at/reply 事实，拆开直接点名与文字弱提及，保持命令路由和去重先后关系。
2. 新增 `onebot/group-context.ts`：有界消息缓存、QQ 到成员代号映射、话题参与状态、到期清理；以纯函数和可注入时钟方便测试。
3. `onebot/group-chat.ts`：扩展闸门输入/原因，用参与候选替代“她刚说过话所以相关”；保留先配置/额度/时间后语义机会的结构。
4. `serve.ts`：接入缓存和话题候选，正确处理混合批次；@ 自己才强制回复；回复发送成功后更新状态。沿用现有按会话串行锁，防止老批次覆盖新状态。
5. `channel-adapter/pipeline.ts`：传递群聊结构化背景/本轮/参与信息，避免历史重复与预算失控；不得把其他人的群消息当成本角色 ASSISTANT 消息。核查 silent 路径的去重/落库/usage，按实际现状设计，不凭本文猜测重写。
6. `chat-reply.ts`：群聊语境独立于 allowSilent；扩展可选决策输出并白名单校验，不影响网页聊天、私聊和旧响应。
7. 更新 QQ 文档 7.1 和 CLAUDE.md 对应约束；必要时仅调整现有模式说明，不重新设计页面。涉及公开接口才改 OpenAPI，涉及 schema 才写 migration；本方案本身不要求两者。

先跑通身份/上下文/决策链，再补 UI 文案。不要顺手重构整个渠道框架。

## 9. 必须覆盖的验收场景

确定性测试验证解析、闸门、状态、校验和发送行为；Mock 模型测试只能证明协议链路，不能宣称已证明真实模型语义判断准确。

1. A @ 自己 → 正常应答，按 QQ 关注 A；A 改昵称后仍同一人，同昵称 B 不是 A。
2. A 不带 @ 继续原话题 → 模型可答/可 silent；A 转去问 B 其他事 → 不自动认领。
3. A @ 自己谈晚饭 → 自己建议吃面 → 其他鱼说火锅 → A @ 其他鱼说昨天吃过火锅：允许补充“那面条有机会了”，不能说“我们昨天吃过”。
4. 从未参与的话题里 A @ 其他鱼问问题 → 跳过；但该句仍可进入有界背景缓存。
5. 普通水群 → 机会闸门放行才调模型，可补充自己的看法，也可 silent。
6. 同名鱼/单字别名出现 → 不强制回复、不绕过安静时段。
7. 一个批次中既 @ 别人，又 @ 自己或有独立闲聊 → 逐条看指向，不能整批误丢。
8. 解析 @全体、多个 @、CQ 字符串、reply 段、引用缺失、self_id 缺失兜底、伪造正文指令。
9. 上下文满/过期、并行话题、群内多线聊天、绑定/群/连接隔离、无关消息不续期、重启后安静降级。
10. 发送失败不记已参与；silent 不生成 assistant；重复事件不二次发送或续期；额度/间隔/群规阻止时不调聊天或视觉模型。
11. @ 自己即使单条且 allowSilent=false，也收到群聊上下文；模型异常返回 silent 时保持现有必回约束的错误处理，不另造额外模型循环。
12. 网页/私聊/公告/B站 口令/表情/视觉/群聊私人记忆隔离不回归。

真实模型用上述语料各试少量轮次，重点记录“未参与却认领别人 @”和“已参与同话题却一刀切退出”两类错误。人工看结果后调提示词，不声称百分百准确。
