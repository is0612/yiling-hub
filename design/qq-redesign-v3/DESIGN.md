# QQ 渠道页 · 行为面板分组重排（方案一）· DESIGN.md

> **受众**：本项目的管理员（单一管理员 + 邮箱注册普通用户，实际使用者就是管理员本人）。
> **核心任务**：在「QQ 渠道」页里配置「她在哪个群、怎么说话、发什么」——一条绑定对应一个「角色 × 号/群」。
> **范围**：`app/components/QqCharacterBehavior.vue` 的行为面板内部结构重组，不改变页面骨架、接口、保存逻辑、状态与错误处理。
> **证据**：`QqCharacterBehavior.vue` 共 1626 行，内含「这个群 / 这个角色」两个 `section.grp` 分组，但三个可展开能力块（语音 / 主动找话 / 群里找话题）混在「这个角色」组里，导致整张面板变成一条分不清层级的长列表。这是「页面乱」的直接来源。
> **关键假设**：现有设计系统 token（`app/assets/css/main.css`）已足够，本次不新增任何颜色 / 字号 / 圆角 / 间距阶；「一行一条绑定」的信息架构保持不变（这是既有产品决策，见 `qq.vue` 注释）。

---

## 1. Visual Theme

运维型后台（Operational SaaS / dashboard 模式）：重复性配置 + 状态监控。视觉上**克制、低装饰、以可扫描性优先**，不做营销化渐变、大图或卡片堆叠。

- 层级靠**明度差 + 间距 + 1px 分隔线**表达，不用阴影分卡片（项目纪律：底色 `#f4f6f9`，卡片才纯白，靠明度差分层）。
- 本次唯一的结构信号：把「绑定级 / 角色级 / 主动能力」三类开关用**三个并列的 section 分组**切开，组标题直接写性质（「只对这条生效 / 所有群共用 / 她主动做」）。

> 观察（来自既有代码）：`.grp` 分组、`.toggle` 开关行、`.more` 折叠块、`.beh-grid` 两列表单、`.dial` 三档刻度这些组件语义都已成熟，无需重画，只需把错误的**归组**纠正。

## 2. Color Palette

全部复用 `app/assets/css/main.css` 既有变量，本次**零新增**。仅列出本面板实际用到的语义角色：

| 角色 | 变量 | 值 | 用途 |
|---|---|---|---|
| 画布底色 | `--bg` | `#f4f6f9` | 页面底色（不在本组件内使用） |
| 卡片面 | `--surface` | `#ffffff` | 行的白砖（外层提供） |
| 次级面 | `--surface-2` / `--surface-3` | `#f8f9fb` / `#f1f3f7` | 按群设置块、状态行、刻度底 |
| 分隔线 | `--line` | `#e6e9ef` | 组间 / 开关行间的 1px 分隔 |
| 主文字 | `--text` / `--text-2` | `#101620` / `#454f5e` | 标题 / 标签 |
| 次级文字 | `--dim` | `#68717f` | 说明文案（AA 下限 5.1:1） |
| 品牌 | `--brand-strong` | `#bf3a63` | 选中态、主按钮 |
| 状态绿 | `--green` | `#0b7a54` | 「已开启」状态 pill |

对比度：沿用项目既有校验值（`--text` 对白 17.4:1，`--dim` 5.1:1），本次未重新计算，直接继承已验收的 token。

## 3. Typography

继续沿用项目全局字体栈 `-apple-system, "PingFang SC", "Microsoft YaHei", system-ui`，字号仅用六档中的 12 / 14（本面板不出现更大字号）。

| 角色 | 字号 | 字重 | 变量 |
|---|---|---|---|
| 组标题（这个群 / 这个角色 / 更多能力） | 14px | 700 | `--text` |
| 组性质说明（grp-tag） | 12px | 400 | `--dim` |
| 开关标题（toggle-copy b） | 14px | 600 | `--text` |
| 字段标签（beh-label） | 12px | 600 | `--text-2` |
| 说明文案（em / beh-meta） | 12px | 400 | `--dim` |

字距保持 0；数字用 `font-variant-numeric: tabular-nums`（已有）。CJK 长文案不截断，靠 `line-height: 1.6–1.75` 换行。

## 4. Component Styles

只涉及本面板已有的组件，本次不动它们的样式，仅调整**归组**：

- **`section.grp`**：一个分组容器。三个实例分别对应「这个群 / 这个角色 / 更多能力」。
- **`.grp-h`**：组标题行，`14px/700` 标题 + `12px/--dim` 性质标签。
- **`.toggle`**：开关行（文案左、`el-switch` 右）。
- **`.more.is-toggle`**：可展开的能力块（语音 / 主动找话 / 群里找话题），折叠头右侧带状态 pill。
- **`.dial`**：三档参与度刻度（仅被 @ / 自然接话 / 所有消息）。

本次新增唯一一条样式规则：`.grp-caps .more.is-toggle:first-of-type { border-top: 0 }` —— 「更多能力」独立成组后，组内第一个折叠块不再画顶线（顶部分隔由 `.grp + .grp` 的 1px 承担），避免双线。

## 5. Layout

展开行 `row-body` 内，面板按纵向三段排列：

1. **这个群**（绑定级）：参与度刻度 → 群号 → 按群覆盖 → 别名 → 说话节奏 → 安静时段 → 参与概率 → 发言限流 → 主人 B站 口令。
2. **这个角色**（角色级）：发表情（+额度）→ 看群里的图 → 偷表情包 → 捡群里的梗。
3. **更多能力**（主动，各带参数）：语音 → 主动找话（私聊）→ 群里自己找话题。

三段之间用 `.grp + .grp`（`border-top: 1px solid var(--line)` + `padding-top: 16px`）分隔。组间距（16px）> 组内间距（12px / 8px），维持「组间距大于组内」的既有纪律。

## 6. Depth And Elevation

扁平布局，**不用阴影**。层级靠明度差（`--surface-2` 块 vs 白底）和 1px 分隔线表达。折叠块用原生 `<details>`，展开态靠 `caret` 旋转 90° 表达，无悬浮层。

## 7. Cautions

- **不要**把「更多能力」组的三个折叠块再塞回「这个角色」组——那是本次要根治的乱源（三个带整套参数的能力块混在一堆纯开关里，视觉上分不清层级）。
- **不要**新增颜色 / 字号 / 圆角 / 间距阶：项目已有严格的设计系统，任何新增都必须先证明现有 token 无法表达。
- **不要**改变「一行一条绑定」的信息架构，也不要改动本组件的任何 prop / 事件 / 保存逻辑——本次是纯结构重组。
- 语义色文字用 `--green`（#0b7a54）这类已加深的值，不要回退到旧值 `#0f8f63`（对比度不达标）。

## 8. Responsive Behavior

- 桌面（>860px）：三段纵向排列，每段内部沿用既有 `.beh-grid` 两列。
- 窄屏（≤860px）：既有 `@media (max-width: 860px)` 已把刻度改纵向列表、`.beh-grid` 改单列、`.pg-row` 改纵向、`.toggle-copy span` 换行——本次分组不影响这些既有规则，三段仍纵向堆叠。
