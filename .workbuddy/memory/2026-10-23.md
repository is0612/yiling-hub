## dev server 起不来（页面 404 / 503）排查与修复

现象：浏览器报 `/api/characters/big-fish`、`.../snapshots` 404，实际 dev server 一直停在 `503 Starting Nuxt...`。

三个独立根因，逐个解决：

1. **Vite 依赖缓存清理被 WorkBuddy 沙箱守卫拦截**
   - 日志：`[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":106,"threshold":50,...node_modules/.cache/vite/client/deps}`
   - shim 路径：`WorkBuddy/resources/app.asar.unpacked/cli/vendor/shim/node-safe-delete-shim.cjs`
   - 含义：Vite 启动时 `fs.rm` 依赖缓存目录（106 条 > 阈值 50）被 guard 抛错，`DevEnvironment.listen` 失败 → dev 永久卡在 Starting。
   - 修复：`mv node_modules/.cache/vite backups/vite-cache-20261023`（3.6M，会自动重建）。**未来每次 vite config 变化触发 re-optimize 时可能复发，同样手法清缓存即可。**

2. **`src/generated/prisma` 整个目录丢失**
   - Nitro 报 `Could not resolve "../../src/generated/prisma/client" from "server/utils/prisma.ts"`，server build 反复重试。
   - 修复：`node node_modules/prisma/build/index.js generate`（generator output = `../src/generated/prisma`，该目录被 .gitignore 忽略，所以 pull/清理后需要重新生成）。

3. **`.env` 缺失 + 数据库无表**
   - `.env` 不存在 → `requireLocalDevOwner` 返回 403（`YILING_LOCAL_API_ENABLED` 未设）。
   - 数据库经 `docker exec` 查无表，但 `_prisma_migrations` 说 no pending（表名是 snake_case：`characters`/`users`，不是 `Character`/`User`）。
   - 修复：按 `.env.example` 重建 `.env`，DB 凭据取自 `docker inspect yiling-hub-db`；然后 `prisma migrate deploy` + `tsx scripts/seed-dev-user.ts`。

## 404 的真凶：前端硬编码 mock 角色 id `big-fish`

上一轮以为是用户手输 URL，实际是**代码里写死的 mock 遗留 id**，点侧边栏必然 404：

- `app/components/AppShell.vue:22-23` 侧边栏「记忆驾驶舱」「周期快照」写死 `/characters/big-fish`
- `app/components/AppShell.vue:34` `isActive` 也按 `big-fish` 字面值判断
- `app/pages/index.vue:77` `filter(c => c.id !== 'big-fish')`
- `app/pages/index.vue:82` 「管理归档计划」按钮跳 `/characters/big-fish/settings/memory`
- `app/utils/mock-data.ts:58` `initialCharacters[0].id = "big-fish"`（仅作 `[id]` 页面的占位骨架，id 会被覆盖，**保留不动**）

修复方式：新增「当前角色」上下文，不再硬编码。

- 新增 `app/composables/useActiveCharacter.ts`：
  - `useCharacterList()` — `useState` 共享角色列表
  - `loadCharacters()` — 拉 `/api/characters`，失败不抛
  - `useCharacterListData()` — `useAsyncData("character-list")`，SSR + 客户端同 key 只拉一次
  - `useActiveCharacterId()` — 路由 `params.id` 优先，否则回退列表第一个；无角色返回 `null`
- `AppShell.vue`：`navigation` 改 `computed`，加 `key` 字段；`isActive(item)` 改按 key 用正则判断；顶层 `await useCharacterListData()` 让首屏 SSR 就拿到真实 id。
- `index.vue`：`characters` 改用共享 state；「下一次记忆归档」卡片改用 `characters[0]`（不再硬编码「大肥鱼」）；mini 列表改 `characters.slice(1, 3)`；按钮动态 href + 无角色时禁用。

验证：8 个页面全部 200；首屏 HTML 里侧边栏已是 `/characters/<uuid>` 与 `/characters/<uuid>/snapshots`；`nuxt typecheck` exit 0；`eslint --quiet` exit 0。

**注意**：直接访问 `/characters/big-fish` 仍是 404，这是 `requireUuid` 的预期行为，没有任何入口再指向它。
