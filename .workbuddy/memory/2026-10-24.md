# 2026-10-24

## 修复 vue-tsc 大量 Prisma 类型报错

现象：`server/api/characters/[id]/memory-settings/*`、`memory-scheduler.ts`、`memory-worker.ts`、
`tasks/[id]/retry.post.ts` 等大量报错，说 `pendingSnapshotIntervalDays` / `rawMessageCleanupEnabled`
不存在、`character` / `memoryScope` 关系不存在。

根因：`prisma/schema.prisma` 已加两个字段，但 `src/generated/prisma` 是旧产物没重生成
（该目录被 .gitignore 忽略，postinstall 里也没跑 prisma generate）。关系报错是连带现象。

处理：
1. `npx prisma generate` → 全部类型错误消失，`vue-tsc --noEmit` 退出码 0。
2. 发现迁移链坏了：`20261024100000_memory_settings_pending_cleanup` 与
   `20261024000000_explicit_raw_message_cleanup_opt_in`、`20261024100000_pending_snapshot_interval`
   重复添加同样的两列（且前两者时间戳撞车），全新库跑 migrate deploy 必然 "column already exists"。
   三个迁移当时都未应用，故 `git rm -r` 删掉冗余的那个，保留另两个。
3. `prisma migrate deploy` 应用 2 个迁移，`migrate status` = up to date，
   information_schema 确认两个列已存在。
4. `package.json` postinstall 改为 `prisma generate && nuxt prepare`，避免重装/新克隆后再次出现此问题。

备注：eslint 仍是 0 error / 1218 warning，纯 vue 格式类告警，与本次无关。
